# 维护约定（面向长期使用）

## 唯一维护源和本机安装

以 Git 仓库 `skills/windows-local-ops/` 为唯一修改源。推荐将 `$CODEX_HOME/skills/windows-local-ops` 建为指向克隆目录的 **Windows 目录联接（junction）**；这样仓库中的修复对本机 Skill 可见，不必复制两份。使用联接前先确认没有同名安装目录；不要覆盖原有数据。若联接不可用，可复制安装，但升级时必须显式同步并校验差异。

`references/host-profile.md` 等机器特有快照应留在本机私有位置（例如 `$CODEX_HOME/local/`），不要提交含用户名、敏感路径、令牌或网络拓扑的快照。公开的仓库只放可以跨机器复用的指令、脚本和非敏感测试。

## 新问题变成新规则的条件

1. **证据**：记录观察到的现象、触发条件、失败命令与工具/PowerShell 版本（去敏）。
2. **原因**：分清环境差异、输出截断、编码问题和工具自身限制，不凭猜测定义问题。
3. **最小修正**：先尝试补一条操作说明；只有重复操作才抽脚本。
4. **回归**：对已修复问题增加最小测试；任何现有脚本修改都需重新验证受影响场景。
5. **版本控制**：一个功能/修复一个逻辑提交，建议如 `fix(output): 标记超长行被截断`。不要自动提交/推送或借维护机会大规模重构。

## 维护后的验收

- 原问题可以稳定复现并正确处理。
- 与原问题无关的 Windows 基础操作没有被新规则阻断。
- Skill 的触发描述能使 Codex 在相关 Windows 任务中选择它，但不把每个任务都变成环境大检查。
- 给使用者报告改了什么、验证了什么、有什么未验证的兼容性风险。
